# Personal Feed — согласованная спецификация

Сервис на Go создаёт отдельный публичный RSS для каждого из 24 источников в `config.yaml`. Alibaba Cloud был указан дважды, поэтому включён один раз. По решению пользователя Google Data Analytics, Fivetran, Jumpmind, Azure Data Factory, Dataddo, Streambed, GitLab, Selectel и Spotify исключены: подписки на их готовые RSS/Atom ведутся напрямую в Inoreader.

## Требования

- Использовать существующий RSS/Atom там, где он доступен и соответствует нужному разделу. Иначе получать статьи через HTML/CSS, при необходимости Chromium или специализированный адаптер.
- Проверять источники каждые 30 минут. При первом успешном обходе включать последние 20 статей; хранить в выдаче последние 100.
- Статья: заголовок, полный текст, оригинальная ссылка, дата, автор и изображения, если доступны. При сбое извлечения полного текста публиковать доступный анонс и ссылку.
- Не создавать дубли при повторных обходах и перезапусках.
- Настройки и источники — YAML, без интерфейса редактирования.
- Docker Compose, обычный публичный HTTP-порт. Домен необязателен. HTTPS настраивается отдельно.
- SQLite `/data/feed.db` на постоянном Docker volume. Статьи, сведения для дедупликации и состояние источников сохраняются между рестартами и пересозданием контейнеров. Изображения сохраняются как URL.
- RSS формируется из базы независимо от исходных сайтов. Сбой одного источника сохраняет его старую ленту и не останавливает остальные. Повторная попытка через 30 минут, ошибка в логах и на странице состояния.

## Не входит

Загрузка полного архива, авторизация, HTTPS, веб-интерфейс настройки, локальная копия изображений, обход платного доступа и CAPTCHA.

## Критерии приёмки

Корректные RSS, проверка всех источников на реальных данных, сохранение состояния после рестарта, дедупликация и лимит 100, изоляция ошибок, инструкция запуска и список ссылок.

## Ограничения внешних источников

Доступность и структура сайтов могут меняться. Подтверждённые результаты и ограничения находятся в `SOURCES.md`. Если исходная лента/список содержит меньше 20 доступных статей, сервис публикует доступные и сообщает об этом. Это ограничение источника или текущего адаптера, а не подтверждение выполнения требования о 20 статьях для него.

Если дата публикации отсутствует, используется дата обнаружения. Для списков без дат порядок определяется исходным списком; закреплённые и рекомендованные статьи могут нарушать строго хронологический порядок. Идентификатор RSS основан на source ID и нормализованном URL. После изменения ID источник считается новым.
