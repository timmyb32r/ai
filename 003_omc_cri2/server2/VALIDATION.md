# Проверки server2

Дата: 2026-09-18. Проверки выполняются локально и в изолированном проекте Docker Compose. Работающий сервер пользователя не изменяется.

## Выполнено

- `go test -race ./...`: все пакеты проходят; 139 тестов/подтестов прошли, 4 проверки пропущены в обычном запуске (опциональные данные или отдельные длительные проверки). Проверены хранение, API, отмена запросов, очередь, перезапуски, обработка китайского и существующие словарные тесты.
- `go vet ./...`: проходит.
- 10 Python-тестов HTTP supervisor проходят, включая зависший native worker, заблокированный IPC, конкурирующие запросы и завершение процессов.
- Дополнительно собран Go-бинарник для Linux amd64 с `CGO_ENABLED=0`. Полные Docker-проверки выполнены на Linux arm64; производительность целевой ВМ отдельно не измерялась.
- Реальный ffmpeg: публикация HLS и остановка без оставшихся обработчиков; отдельный тест процесса, закрывшего stdout и зависшего, подтверждает принудительное завершение за ограниченное время.
- SQLite: IDs и история после повторного открытия; ошибка записи/ENOSPC без публикации отсутствующего аудио; восстановление после незавершённой публикации; повторяемая очистка после ошибки удаления; отказ второго писателя в тот же volume.
- Снимки: неизменный порядок/состав при пагинации и очистке, удержание активных файлов, срок действия, освобождение и ограничение количества.
- Ресурсы API: ограниченные SSE и медленные клиенты, 8 тяжёлых ответов не блокируют аудио и health, ограничения JSON не приводят к молчаливому обрезанию.
- Китайский: многосимвольные токены, положительные интервалы слов, полнота ответа HanLP, чтение слова на границе фрагмента, сохранение настоящих повторений слогов.
- Модели: настоящая SenseVoice с исходными весами и HanLP с исходным кешем запускаются с read-only mounts и отключённой внешней сетью. Повторные запросы используют прежний процесс модели.
- Реальный ASR через HTTP: 20 одинаковых запросов китайского образца; результаты совпали, PIDs не изменились, FDs процессов остались 8/4/8. Это короткая проверка повторного использования, не длительный тест модели.
- Точность привязки кодека: 63 секунды, 22 HLS-фрагмента, 21 звуковой маркер. Компенсируется постоянная задержка 1105 сэмплов (69,0625 мс). Проверены FFmpeg 8.1.2 на macOS и FFmpeg 5.1.9 в Debian. Остаточная ошибка определения маркеров менее 0,03 сэмпла; это проверка общей шкалы времени, не точности распознавания слов моделью.
- Собраны все три Docker-образа. Веса моделей в слои образов не копируются.
- Полный Compose: настоящее аудио → SenseVoice → HanLP → все словари → SQLite → HLS/JSON; проверены субтитры, пиньинь, временные границы и полное скачивание снимка. В повторной проверке финальной сборки получены 4 фрагмента, 16 слов с временными метками и 97 760 байт аудио, без отброшенных заданий. [Машиночитаемый результат](validation/real-compose.json).
- Рестарт Go-контейнера: сохранились метаданные, текст, SHA-256 аудио и снимок фрагментов 0–5. После рестарта опубликованы новые ID 10–17; процессы моделей не перезапускались.
- Android: 142 unit-теста проходят, debug APK и инструментальный APK собираются. Проверены разрывы времени, точность трёхчасовой записи, неполные скачивания, адаптивная пагинация при HTTP 413, отмена и полный таймаут HTTP, сохранение прежнего архива при ошибке индекса и конкурентная публикация загрузок.

## Измерения с настоящими данными

Все существующие словари: около 1297 МиБ живой Go heap после GC. Поэтому основной контейнер ограничен 2560 МиБ, а `GOMEMLIMIT` — 1792 МиБ.

Пики cgroup memory при полном Compose-запуске:

| Сервис | Измеренный пик | Лимит |
|---|---:|---:|
| Go + ffmpeg + словари | 2112 МиБ | 2560 МиБ |
| SenseVoice | 594 МиБ | 1536 МиБ |
| HanLP | 406 МиБ | 2048 МиБ |

Это измерения локальной Docker VM, а не производительности пользовательского сервера. Общий лимит контейнеров — 6 ГиБ / 4 CPU.

## Финальные проверки

Десятиминутный прогон с `-race` прошёл: настоящий ffmpeg, пять HTTP-клиентов, периодическое завершение источника и очистка 30-секундной тестовой истории. ASR в этом прогоне детерминированный; настоящая модель проверялась отдельно выше.

| Показатель | Результат |
|---|---:|
| Опубликованные фрагменты | 204 |
| Переподключения | 17 |
| FD под нагрузкой | 21–23 |
| FD до запуска / после закрытия | 6 / 6 |
| Goroutine под нагрузкой | 26–32 |
| Goroutine до запуска / после закрытия | 2 / 3 |
| Живая Go heap под нагрузкой | 2,55–5,17 МиБ |
| Максимальный размер тестового архива | 832 512 байт |

Это проверка конвейера и жизненного цикла, а не размера памяти настоящих словарей/моделей. Их измерения приведены отдельно. [Полный журнал](validation/soak.log), [результат рестарта Compose](validation/restart.json), [результат Android](validation/native-android.json).

Первый прогон отметил одиночный всплеск goroutine 29 → 47 с последующим возвратом к 26–29. Проверка уточнена: теперь она выявляет устойчивое превышение в минутном окне и дополнительно требует освобождения FD/goroutine после остановки, с дампом при нарушении. Повторный полный прогон прошёл.

Нативная [проверка HLS-разрыва](../android/tools/NATIVE_HLS_SMOKE.md) прошла на одноразовом Android 34 arm64 эмуляторе с настоящим декодером Media3. Оба независимых MP3/TS-фрагмента декодируются; временная шкала субтитров правильна до и после пропуска в 300 секунд; событие пропуска приходит ровно при его достижении; воспроизведение продолжается без ожидания пропущенных 300 секунд. Перемотка в пропуск переводит к следующему фрагменту. Первоначально запуск блокировался нехваткой локального места, затем доступное место увеличилось и проверку удалось выполнить. Личные AVD и физические устройства не изменялись.

## Границы гарантий

- Потеря входного эфира, переполнение пятиминутной очереди или полный рестарт процесса могут создать явно отмеченный пропуск. Опубликованные записи остаются долговечными.
- Пиньинь и временные оценки внутри многосимвольного ASR-токена остаются оценками модели/словарей. Не применяется удаление повторяющегося текста по одному совпадению букв: оно удаляло бы и настоящие повторения.
- Тест искусственной нехватки места проверяет пути ошибок, но не заменяет наблюдение за реальным диском и остальными приложениями на хосте.
- Настройки рассчитаны на пять клиентов. Ошибки ограничения ресурсов возвращаются явно; бесконечных очередей и обещания обслужить произвольную нагрузку нет.
