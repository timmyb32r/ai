# Ralplan

1. Draft a plan from verified repository context and explicit acceptance criteria.
2. Review it through an architecture lens: boundaries, interfaces, compatibility, operations, and long-term cost.
3. Review it through a critic lens: missing steps, untested assumptions, scope creep, rollback, and falsifiable completion evidence.
4. Reconcile disagreements explicitly; do not hide tradeoffs behind vague consensus.
5. Repeat once when material objections remain. Use sub-agents for independent lenses only when explicitly requested and available.
6. Return the final plan, rejected alternatives, unresolved decisions, and verification matrix.
7. Wait for explicit implementation authorization.
