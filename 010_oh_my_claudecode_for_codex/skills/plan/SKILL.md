# Plan

1. Inspect project instructions, relevant code, tests, and existing patterns.
2. Ask only questions that materially alter the plan and cannot be answered locally.
3. State assumptions, non-goals, risks, and acceptance criteria.
4. Present design options only when they create a real tradeoff; recommend one explicitly.
5. Produce 3–8 dependency-aware steps with concrete files or components and verification per step.
6. In review mode, test references and assumptions, then return a clear approval or revision verdict.
7. Do not begin implementation in a planning-only request.
